# 持仓快照与数据验证

先读 [数据契约](references/data-contract.md)。本模块是组合诊断、风控和条件交易计划的输入门禁；数据来源可用不等于持仓已接入。

1. 从当前任务指定的私有数据根、用户导出或已确认的账户账本读取。解析实际路径与更新时间，记录 binding；不要把历史示例、watchlist、模拟账户或旧 Claude/Claw 记录升级为真实持仓。
2. 明确快照日期、是否覆盖全部投资账户、是否还有待确认成交/申赎、是否由用户确认。空数组不代表空仓；未确认空仓使用 `unknown`。
3. 规范证券代码、交易所、基金份额类别与账户别名；保留前导零。按账户、代码、份额类别查重；同一标的跨账户可以合并分析，底稿仍分开。保留原来源和更正历史，不静默去重。
4. 股票和 ETF 使用真实非复权交易价格估值，复权序列只用于一致口径的收益分析；场外基金使用已披露的对应份额净值及净值日期。估算净值单独标 `estimate`，不充当正式净值或成交价。货币基金按产品披露方式核对，不将七日年化收益率当作净值。
5. 检查数量、成本、可用份额、冻结/在途、现金、估值币种、时间戳、价格来源。多币种未取得同日汇率前不汇总成人民币。成本缺失时不计算成本收益率；未知字段保持 null。
6. 根据用途设定并记录最大数据年龄。用 `scripts/validate_snapshot.py INPUT --now ISO时间 --max-age-hours N` 检查格式、重复、有效期和对账；N 来自本次用途，不是所有市场的固定承诺。通过脚本后仍须确认来源真实性、市场时段与交易限制。盘前前收盘价可用于预案，不称盘中可执行价格。
7. 输出 `snapshot`、`validation`、未解决字段和可继续的研究范围。验证失败不得更新为可执行持仓，不自动生成零金额或补齐虚构份额。

私有输入模板见 [snapshot.template.json](assets/snapshot.template.json)。模板故意不含真实资产、行情和成交。重复运行按 `snapshot_id + source_ref` 去重；用户更正用 `supersedes`，不覆盖源文件。程序只读输入并输出校验结果，不调用券商或发送消息。
