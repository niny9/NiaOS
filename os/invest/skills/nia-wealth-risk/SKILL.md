# 仓位风控与回撤

输入为通过 holdings 校验的快照、带日期的净值/现金流序列、用户风险政策及本轮拟议计划。政策记录版本、确认来源、生效日；未给风险承受能力、现金底线、最大单一证券/行业仓位或回撤阈值时使用 unknown，不能私设 10%/20% 阈值后宣称通过。

1. 同时列投资账户总资产、可用现金、风险资产和全部净资产，分母写清。房产不能充当股票账户现金；冻结、在途和应急储备不重复计算为可买额度。
2. 计算直接证券、行业、基金公司/策略的集中度；有底层披露时补穿透估算及覆盖率。相关矩阵仅在样本和对齐日期足够时计算，无样本不能写“低相关”。
3. 回撤用剔除外部出入金影响的单位化投资净值或链式收益序列。当前回撤 `NAV_t / running_peak - 1`，区间最大回撤取该序列最小值；同时注明起止日、估值频率和复权/分红口径。短序列不称全历史最大回撤。只有资产余额时可列余额下降，不能直接叫投资回撤。
4. 对已持仓和拟执行后组合分别对照限额。无有效净值序列/政策/持仓覆盖时为 unknown；明确已越限为 block，接近用户预警线为 warn，全项有证据且通过才 pass。不把未知项排除后算整体通过。
5. 压力情景标明是假设，按风险资产跌幅、基金赎回延迟、房产流动性折价和收入减少分别看现金缺口。不能把情景概率或损失上限冒充已校准事实。
6. 输出触发项、当前值、阈值/来源、对计划影响和恢复条件。block 时仍可研究降低风险的人工方案，但没有可卖份额与现行规则不能给可执行数量。

收益目标不能倒逼提高杠杆或突破限额；目标难以达成时交由 goals 调整储蓄、收入、支出或期限假设。只报告风控，不自动平仓、不修改用户政策、不发送未授权提醒。
