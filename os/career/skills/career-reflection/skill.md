# Career Reflection Skill

当用户提供工作case时，使用Career Learning Log框架生成系统性的复盘与成长md文件。

## 输入

用户会提供以下一种或多种形式的内容：
1. 工作case描述（发生了什么事）
2. 踩坑经验（哪里做错了）
3. 公司/领导反馈（别人怎么看）
4. 项目总结（做了什么项目，结果如何）
5. 能力提升感受（觉得哪里变强了）

## 处理流程

### Step 1: 读取框架文件
首先读取：
- `/Users/niny/career-os/reflections/README.md` - 了解当前问题优先级
- 用户最近一次的复盘文件（如果存在）

### Step 2: 结构化提取

从用户输入中提取：

#### A. Experience（E01-E18）
- 踩过什么坑？
- 别人提醒过什么？
- 哪些错误以后不能重复？
- **格式**: 具体场景 → 问题表现 → 根本原因 → 改进方向

#### B. Judgment（J01-J05）
- 面对同样的问题，以后应该怎么判断？
- 逐渐建立的产品原则、组织原则和决策原则
- **格式**: 场景 → 判断原则 → 实战案例（正确/错误对比）

#### C. Capability（L1-L7）
- 真正掌握了什么能力？
- 不是"知道AI Eval是什么"，而是"真的设计过、跑过、迭代过"
- **格式**: 能力层级 → 当前成熟度（0-4分）→ 证据

#### D. Evidence
- 能力的证据：项目、指标变化、复盘、解决的问题、复杂沟通、失败后的新方法
- **格式**: 具体case → 结果 → 能力体现

### Step 3: 对照七层能力地图

| Layer | 能力 | 核心问题 |
|---|---|---|
| L1 | 职场生存 | 别人是否愿意继续跟我合作 |
| L2 | 沟通与组织 | 我能不能理解人、权责、资源和场域 |
| L3 | 产品基本功 | 我能不能把模糊需求变成明确问题 |
| L4 | 数据与商业 | 我能不能判断事情值不值得做 |
| L5 | AI产品 | 我能不能把不稳定模型变成稳定产品 |
| L6 | 技术协作 | 我能不能真正和研发/算法讨论方案 |
| L7 | 产品判断力 | 我能不能在复杂信息中做正确取舍 |

评估用户的case属于哪一层，当前成熟度如何。

## 关键原则

### 1. 第一性原理
不停留在第一层答案，至少连续问3-5层"为什么"

### 2. 事实与推演分开
- Fact: 实际发生了什么？
- Interpretation: 我是怎么理解的？
- Action: 需要什么行动？

### 3. 能力成熟度标准
- **0分**: 第一次意识到这个概念
- **1分**: 知道原理和方法
- **2分**: 偶尔能做到
- **3分**: 基本每次都能做到
- **4分**: 能教别人

### 4. 证据优先
不记录"我觉得我会了"，只记录"我真的做过、结果如何、学到什么"

### 5. 控制篇幅
每次复盘控制在2000字以内，只记录最核心的内容

## 注意事项

1. 不要编造数据和项目，只基于用户提供的真实case
2. 不要堆砌所有框架，只用到与case相关的部分
3. 每次复盘聚焦1-3个核心问题，不要面面俱到
4. 行动计划要具体可执行，不要写空话
5. 能力评分要诚实，不要虚高
