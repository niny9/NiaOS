# 项目进展 → 原子能力证据

复用 [career-weekly-review](../skills/career-weekly-review/SKILL.md) 与其 [integration.md](../skills/career-weekly-review/references/integration.md)。这是收到项目材料时的增量入口，不新增评分体系、周报、调度器或第二个事实库。

## 触发与写回顺序

用户提供项目周报、PRD、截图、口述更正或推进结果时，主动执行本流程，无须用户再次要求归档。按现有绑定找到唯一私有数据根；其余历史目录只读。

1. 读完本批来源，分别记录事件时点、材料时点与录入时间。OCR 待辨字和未核实结论保留疑点，AI 摘要不能单独升级成事实。
2. 沿用项目 ID；现有工作流按 ID 更新。登录至少区分入口优化、联登和免登；月卡区分即买即用与我京心智透传。新项目或新工作流先由调用方按现有台账规则建档，当前 CLI 不自动推断创建。
3. 为每个项目变更补入原子能力证据：个人行动、来源、阶段、本人职责与限制。没有合格能力证据时进入既有待补队列，不能凭进度文字制造证明。
4. 用候选 batch 校验原值、来源与 ID，再生成差异；事实库、工作流表、能力表和项目笔记一起更新。`date` 为录入时间，`as_of` 可明确实际材料/事件时点；未提供时保留原事实时点，不把历史补录升级为今天的新进展。
5. 回读验证、保存旧值和变更记录。按已有 Log / Registry 写入位置引用证据，不能用本模块另建职业总账。
6. 把新增证据交给既有十二维周检和 Resume Asset Gate；没有结果归因就只写设计/推进，不升级等级、不改成业务成果。公开同步另走白名单脱敏审查。

## 增量数据约定

在独立候选文件中提供 `reviewed: true`、`date`、`source_ids`、新增 `sources`、`updates`。`reviewed` 是调用者确认读源的记录，不是脚本自动核验。每项 update 包含 `project_id` 和非空 `capabilities`；scalar 与 stream 字段都使用 `{previous, value}`。相同 batch 内容重复执行不再入账，冲突原值必须先解决。

新增能力证据使用新的稳定 evidence ID；不能覆盖同 ID 的旧证据。`level_change` 固定为零；只有后续周检凭完整证据才评估能力等级。合法阶段为 `documented_design / reported_milestone / verified_release / verified_result`；阶段名称不自动证明其真实性。

## 执行与验收

[标准库脚本](../project-evidence/scripts/project_evidence_sync.py) 支持 dry-run、重复批次去重、原值检查、来源检查、项目与能力同步生成、笔记历史保留和旧版备份。输入输出路径由调用方显式传入，不能硬编码个人目录或默认向公开仓库写入。

验收至少检查：新增事实与原子能力同批出现；登录和月卡各子链路不遗漏；事件日期未被录入日期覆盖；未提升能力等级；未把目标/评审变成发布；重复执行无重复记录；历史笔记未丢失。任何失败进入已有 pending/failed 清单，不宣称完成。

本次本地历史资料已有逐图核对与私有归档。公开包只包含[脱敏项目快照](../project-evidence/README.md)及可移植脚本；不表示未来自动任务已执行成功。

## 来源与写入边界（2026-11-07）

多项目batch必须在各update声明source_ids，多来源多工作流需在stream更新内声明source_ids；能力证据只能引用该项目本批审核过的来源，每次进展至少新增一条能力证据。未知项目/工作流明确报错。笔记as_of保留事实时点；recorded_at为录入时间。CLI支持macOS/Linux，使用同库文件锁和逐文件原子替换；锁忙时退出并要求重试，不并发覆盖。跨文件失败可在修复后幂等重跑；外部笔记修改另做原文比对。
